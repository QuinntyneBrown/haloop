# L1 - High-Level Requirements

## L1-001: Browser Capability Detection & First-Run Onboarding
The system must detect required browser capabilities (Chrome built-in Gemini Nano APIs, WebGPU, Web Bluetooth, WebAssembly, and persistent local storage), route incompatible browsers to a capability fallback offering CPU WebAssembly mode, and guide first-time users through initial on-device setup.

## L1-002: Application Shell, Navigation & System Status
The system must provide a persistent application shell for navigating primary routes (`Today`, `Train`, `Coach`, `History`, `Devices`, `AI Lab`, and `Settings`), displaying live device and on-device AI status indicators, surfacing global system status banners, and handling unknown routes with an in-shell 404 page.

## L1-003: Daily Dashboard (Today)
The system must present a daily overview displaying the user's greeting, active streak, sensor readiness, daily Scripture with on-device translation support, today's planned movement session with exercise breakdown, weekly readiness KPIs, and direct launch actions into training and coaching.

## L1-004: Live On-Device Workout Studio (Train)
The system must execute live guided and free-form workouts using local camera-based pose estimation for rep counting and form scoring, spoken coaching cues, hands-free voice commands, live Bluetooth wearable telemetry, pause and resume controls, audio-only fallback when camera access is blocked, and a completion flow with optional devotional or training reflection notes.

## L1-005: On-Device AI Coach & Semantic Scripture Search
The system must provide a private, on-device conversational coach powered by Chrome's Gemini Nano Prompt API (with an optional local open-model fallback) for workout adjustments and devotional reflection, paired with on-device semantic Scripture search over the KJV index and local translation across 12 languages.

## L1-006: Workout History, Filtering & Session Detail
The system must persist completed workouts locally and provide a searchable, filterable workout history with on-device weekly and per-session recaps, full session metrics and devotional notes, and one-action session repeat.

## L1-007: Web Bluetooth Wearable Device Management
The system must enable users to discover, label, pair, monitor, and disconnect Bluetooth Low Energy (BLE) fitness sensors directly from the browser without a companion app or cloud relay, surfacing real-time connection, disconnect, and low-battery status notifications.

## L1-008: On-Device AI Model & Capability Management (AI Lab)
The system must report the availability of Chrome built-in Gemini Nano APIs (with step-by-step flag enablement guidance when disabled) and enable users to download, monitor, remove, and manage the local cache budget for Hugging Face open models executed via Transformers.js on WebGPU or WebAssembly.

## L1-009: User Preferences & Local Storage Configuration (Settings)
The system must enable users to configure and persist local preferences—including display name, Scripture language, preferred inference backend, model cache budget, and spoken workout cues—with validation and immediate application.

## L1-010: Local-First Offline Resilience & Storage Integrity
The system must operate offline for training, coaching, voice commands, pose estimation, history, and Scripture search using cached models and local browser storage, while detecting and recovering gracefully from offline transitions, storage quota exhaustion, private browsing restrictions, and locked or corrupted local records.

## L1-011: Privacy & Security
The system must process all camera video, microphone audio, wearable telemetry, coaching conversations, and workout records strictly on-device with zero remote upload, enforce input validation and output sanitization against XSS and injection attacks across all user-entered fields, isolate browser hardware permissions, and secure external links.

## L1-012: Performance & Resource Efficiency
The system must maintain responsive UI interactions and real-time workout feedback during on-device AI inference, execute ML workloads off the main thread, enforce the configured model cache budget, and degrade cleanly to WebAssembly CPU execution when WebGPU is unavailable.

## L1-013: Responsive Design, Theming & Accessibility
The system must adapt seamlessly across extra-small (<576px), small (>=576px), medium (>=768px), large (>=992px), and extra-large (>=1200px) viewports, support light and dark themes plus reduced-motion and high-contrast preferences, and conform to WCAG 2.2 AA accessibility standards.
