Notifications

Toasts vs persistent banners, stacking rules, auto-dismiss timing and live-region politeness.

WCAG 2.2 AAPattern

  • When to use
  • Structure
  • States

Overview

Notifications keep users informed about background downloads, Bluetooth sensors and connectivity without stealing focus.

When to use

  • Toast: transient confirmation or sensor event (model cached, Polar H10 connected).
  • Banner: persistent global status (offline mode, WASM fallback).

Structure

Model cachedViTPose is ready offline.

States

Stack up to 3 toasts vertically; auto-dismiss info/success after ≥ 8s (pausing on hover/focus); persist danger toasts until dismissed.

Responsive behaviour

Toasts span full width at the bottom below 640px and dock bottom-right (24rem) at 640px+.

Accessibility

Use role="status" (polite) for routine updates and role="alert" (assertive) only for errors.

Content

Keep notification copy scannable in under 2 seconds.
