Feedback & loading

Choosing the right feedback channel: skeletons, spinners, progress bars, inline status, toasts and alerts.

Overview

Every asynchronous action in Haloop gives immediate, proportional feedback without startling the user or shifting layout.

When to use

  • Initial screen load: Skeleton matching final geometry.
  • Measurable work (> 2s): Progress bar with MB/percent readout.
  • Short indeterminate work: Spinner or button aria-busy="true".
  • Background completion: Toast.
  • Persistent system state: Alert / banner.

States

Loading states transition cleanly into loaded, empty or recoverable error states with zero layout jump.

Responsive behaviour

Skeletons mirror the responsive grid; progress bars fill their column.

Accessibility

Announce completion via role="status" and urgent failures via role="alert"; pause decorative shimmers under reduced motion.

Content

Always state concrete numbers (MB downloaded, % complete) and name the operation.
