Dialogs & overlays

Choosing between modal dialogs, bottom sheets, dropdown menus and tooltips.

WCAG 2.2 AAPattern
  • Overview
  • When to use
  • Structure
  • States
  • Responsive
  • Accessibility

Overview

Overlays preserve context while isolating a focused decision. Haloop never stacks two modal dialogs on top of each other.

When to use

  • Modal dialog: confirmations (Remove model) and short focused tasks (Pair device, Finish workout, Search Scripture).
  • Dropdown menu: 3+ secondary actions behind a single trigger.
  • Tooltip: short text hints for icon-only controls.

Structure

Remove cached model?

States

Dialogs support default, busy (aria-busy="true"), invalid (inline errors) and failed (inline danger alert) states.

Responsive behaviour

Dialogs become full-width bottom sheets below 640px and centred modals at 640px+.

Accessibility

Trap focus inside open dialogs, mark background content inert, close on Esc, and restore focus to the triggering button.

Content

Name the specific object in confirmation dialogs ("Remove ViTPose (94 MB)?").
