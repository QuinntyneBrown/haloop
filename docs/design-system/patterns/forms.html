Pattern · Composition

Forms

Consistent layout, blur validation, error summaries, busy submits and destructive confirmations.

WCAG 2.2 AAPattern
  • Overview
  • When to use
  • Structure
  • States
  • Responsive
  • Accessibility
  • Content
  • Do and don't
  • Sources

Overview

Haloop forms (Settings, Welcome & setup, Finish workout, Pair device) follow a single-column rhythm capped at 65ch, with labels above controls and explicit validation recovery.

When to use

  • Use a full page form for multi-section preferences (Settings).
  • Use a modal dialog form for short, contextual entries (Finish workout, Pair device).
  • Use a destructive confirmation dialog before removing cached models.

Structure

States

Validate on blur after the field is touched, re-validate on input while invalid, show a top .form-summary on invalid submit, set aria-busy="true" on the submit button while saving, and confirm success via an inline alert or toast.

Responsive behaviour

Single column at all viewports below 768px; primary submit button stretches full width on phones when appropriate.

Accessibility

Move focus to .form-summary on submit failure; link every summary item directly to its invalid field ID; connect inline errors via aria-describedby.

Content

Mark optional fields with (optional) instead of asterisks; use verb-first submit labels like "Save preferences".
