Alert & banner

Inline contextual alerts and full-width system status banners in four semantic tones.

WCAG 2.2 AAStatus: stablerole="status" / role="alert"

Overview

Use inline .alert blocks inside pages and dialogs for actionable warnings (like WASM fallback or form errors), and full-bleed .alert.banner strips at the top of the workspace for global offline or browser status.

Anatomy

  1. 4px semantic left stripeTinted background + matching border.
  2. Icon20px semantic status icon.
  3. Body & actionsTitle, message and optional inline recovery links.

Variants

Gemini Nano readyPrompt, Summarizer and Translator APIs are active locally.
Preferences savedYour on-device settings are updated.
Offline modeCached models work normally; new downloads pause until you reconnect.
Camera permission blockedAllow camera access in Chrome settings to count reps.

Sizes

Alerts use --space-4 padding.

States

Responsive behaviour

  • Banner actions wrap neatly onto a second line below 640px.

Theming

Uses component tokens --alert-bg, --alert-fg, --alert-border and --alert-icon.

Accessibility

Role and pattern

Use role="alert" only for newly injected urgent errors; static banners use role="status" or plain landmark text.

Keyboard

KeyAction
TabReaches action links and dismiss button.

Focus

Focus ring on action links and close button.

Labelling

Never rely on colour alone: every alert carries an icon and clear title.

Contrast

Info text on info bg
Success text on success bg
Warning text on warning bg
Warning icon on warning bg
Danger text on danger bg

Motion

None.

Touch

Close button meets 24px minimum.

Content

  • Explain the impact and the recovery action in two short lines.
