Foundation · Inclusive design

Accessibility

WCAG 2.2 AA built into contrast tokens, shared focus rings, target sizes and WAI-ARIA component contracts.

WCAG 2.2 AA4 interaction tokens
  • Overview
  • Commitments
  • Testing
  • Tokens

Overview

Haloop targets WCAG 2.2 Level AA by construction. Accessibility is baked into the tokens (contrast, focus ring, target sizes, reduced motion) and into every component's semantic HTML and WAI-ARIA pattern.

System commitments

PrincipleWCAG SCHaloop rule
Perceivable1.4.3, 1.4.11, 1.4.1, 1.4.4, 1.4.10, 1.1.1, 2.3.3≥ 4.5:1 text contrast and ≥ 3:1 UI/focus contrast in both themes; never colour alone; 100% rem sizing; reflows to 320px; aria-hidden on decorative SVGs; reduced-motion zeroes durations.
Operable2.1.1, 2.1.2, 2.4.1, 2.4.3, 2.4.7, 2.4.11, 2.5.8Full keyboard operability; skip link to #main; shared 2px focus ring with 2px offset; ≥ 24px min target and 44px comfortable target; no traps outside modal dialogs (Esc closes).
Understandable3.1.1, 3.2.3, 3.3.1, 3.3.2, 3.3.3, 3.3.4Visible labels on every control; inline error messages + top error summary linked via aria-describedby; confirmation dialogs for destructive actions like removing cached models.
Robust4.1.2, 4.1.3Native HTML first (button, a, input, select, details); live regions (role="status" / role="alert") for toasts and save indicators.

Testing procedure

  1. Run check_contrast.py after any palette or semantic colour change (must pass 100%).
  2. Run check_design_system.py to verify landmarks, headings, labels, accessible names and links.
  3. Keyboard-tab through interactive examples and verify focus visibility in both light and dark themes.
