Theming

Three-tier token architecture powering light paper, dark ink, OS preference detection and DTCG tokens.json.

  • tokens.json

Overview

Haloop supports two first-class themes — Light (warm linen paper, default on :root) and Dark (deep ink, activated via [data-theme="dark"] or OS prefers-color-scheme: dark) — plus automatic overrides for prefers-contrast: more and Windows forced-colors: active.

How themes work

  1. Primitives (--palette-*) never change between themes.
  2. Semantic tokens (--color-*, --shadow-*) are overridden inside [data-theme="dark"] and @media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }.
  3. Component tokens (--btn-bg, --card-bg, --alert-bg) alias semantic tokens, so components adapt automatically without theme selectors.
  4. color-scheme: light | dark is declared per theme so native scrollbars and form controls match.

Adding a new theme

Create a [data-theme="<name>"] block overriding semantic tokens only, add the theme name to contrast-pairs.json checks, and run check_contrast.py.

[data-theme="high-energy"] {
  --color-accent: var(--palette-halo-600);
  --color-fg-on-accent: var(--palette-white);
}

Consuming tokens.json

tokens/tokens.json exports all 278 tokens in W3C Design Tokens Community Group (DTCG) format, including light/dark overrides under $extensions, ready for Angular/Tailwind/CSS custom property pipelines.
